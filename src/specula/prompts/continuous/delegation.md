## Parallel Subagents

Your agent CLI may let you delegate work to subagents. The skills' parallelization guidance applies as written (for example, code analysis runs one subagent per major source file and verifies issues and commits in batches); the rules below add to it.

- Writes stay with you. Only you write the shared artifacts (`modeling-brief.md`, `base.tla`, `MC.tla`, `Trace.tla`, harness code). A subagent investigates and returns conclusions with `file:line` evidence and paths, not edits to shared files.
- Each subagent keeps its own notes file, `{{notes_dir}}/sub-<topic>.md`, and appends each result as soon as it has verified it: the claim, its `file:line` evidence, what it ran and observed, and the paths of its programs and logs. It does not hold its results back for one final report; its final reply is a short summary and that path. Put this in every subagent prompt.
- If a subagent's reply is missing, truncated, or blocked, read its notes file and the artifact paths it used, and re-cover the scope they leave uncovered, with a narrower subagent or yourself, before you treat that area as covered.
- Good units to fan out are independent investigations: deep analysis of one module or file; a batch of issues or commits to verify; the history of one component; the code facts behind one action while you write the spec; the instrumentation points of one component; and, during validation, the diagnosis of one failing trace or the Case A/B/C triage of one counterexample. Subagents may build the system and run probe programs.
- A clean context reviews best where self-assessment is weakest. After you synthesize the Scenarios, a fresh subagent can challenge them (overgeneralization across modules, missing evidence, unsupported claims) before you revise them; after you write the base spec, one can check its fidelity against the code.
- Keep tightly coupled sequential reasoning, a counterexample derivation in progress, and anything that needs this session's accumulated context to yourself. Do not start confirmation agents; Specula runs confirmation.
- Run subagents in the foreground: issue independent subagent calls together so they run in parallel, and integrate their results before you end your turn.
