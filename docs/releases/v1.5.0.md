# Specular v1.5.0 — Specula is now Specular

Specula is now **Specular**. This release also includes everything developed since v1.2.0: some updates for frontier models, liveness checking, and an experimental single-session mode.

## Switching from Specula

Existing installs need a one-time switch. Until you switch, the old `specula` command prints these steps and exits.

1. Let runs in progress finish first. Runs started before the switch cannot be resumed afterwards.
2. Rename environment variables from `SPECULA_*` to `SPECULAR_*`, including GitHub Actions repository variables, and replace `specula ci` with `specular ci` in CI workflows. The updated [workflow template](https://github.com/specular-org/Specular/blob/v1.5.0/examples/ci/specular-ci.yml) runs on runners labeled `specular`. Specular stops and lists any old variable names it finds.
3. If you used the sandbox, move its policy file: `mkdir -p ~/.specular && mv ~/.specula/sandbox.json ~/.specular/`.
4. Update the checkout, replace the command, and refresh the agent integration:

   ```bash
   git fetch origin --tags
   git checkout v1.5.0
   uv tool uninstall specula && uv tool install -e .
   specular setup
   specular --version
   ```

Run outputs now go to `.specular-output/`. Existing CI directories keep working; the first incremental run updates helper scripts that still refer to the old names. See [Switching from Specula](https://github.com/specular-org/Specular/blob/v1.5.0/docs/Usage.md#switching-from-specula) for details.

## Highlights since v1.2.0

- **Confirm bugs before modeling.** `--confirm-first=only` reproduces the bug candidates from code analysis right away, before any model is built; `--confirm-first=continue` then runs the full workflow.
- **Liveness checking.** Modeling briefs cover liveness properties, generated specs include liveness patterns, and model checking runs liveness configurations and classifies liveness counterexamples.
- **Scope-scaled guidance.** Modeling guidance and verification scale to the scope you request.
- **Single-session mode (experimental).** `--orchestration=single-session` runs analysis through validation and repairs in one agent session.
- **Reliability.** Fixes to resume and confirmation (verdicts bound to the inspected snapshot, repair limits kept across resume, recovery after partial repairs), TLC cleanup and timeouts, rate-limit retries, Claude Code safeguard refusals handled as policy blocks, per-invocation cost for resumed sessions, and macOS compatibility.
