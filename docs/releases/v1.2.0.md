# Specula v1.2.0 — Continuous Verification

Specula v1.2.0 adds continuous verification: initialize a model and trace harness once, then evolve and check them as your code changes. This release also supports importing existing verification assets and carrying unresolved findings across runs.

## Highlights

- **Persistent, incremental CI.** `specula run --ci-init` establishes a baseline in a persistent `--ci-dir`. Later `--incremental` runs inspect the source changes, update the model and harness, validate traces, check properties, and confirm findings. Interrupted runs can resume their original agent conversation.
- **GitHub Actions integration.** `specula ci` and the supplied workflow support pushes, same-repository PRs, merge queues, scheduled checks, and manual runs. PR checks leave the branch baseline unchanged; matching completed results can be reused after merge, including squash and rebase merges.
- **Bring Your Own Model.** `--byom=PATH` accepts a TLA+ model or a directory of verification assets for an ordinary run or CI initialization. Specula reuses usable assets, fills missing parts, and writes a modification report.
- **Persistent findings.** Unresolved findings carry forward in CI and can be imported into a new single-target run with `--findings-from=PATH`. Reuse requires matching the issue and checking its dependencies and assumptions; resolved findings leave the active history.
- **Long-running workflow improvements.** Incremental CI supports native context compaction and configurable recovery. TLC startup and wait tools, preserved pipeline logs, and fixes to resumed review routing and confirmation snapshots improve execution and diagnosis.
- **Updated case studies.** The pinned archive includes NVFlare, Temporal, CloudNativePG, vsr-rs, Nanvix, Solr Operator, and SlateDB additions, along with further CometBFT reproducers and revised libspdm classifications.

See the [CI guide](https://github.com/specula-org/Specula/blob/v1.2.0/docs/Usage.md#add-specula-to-ci), [Actions template](https://github.com/specula-org/Specula/blob/v1.2.0/examples/ci/specula-ci.yml), and [BYOM guide](https://github.com/specula-org/Specula/blob/v1.2.0/docs/Usage.md#bring-your-own-model-byom) to get started.

## Upgrade

From your existing Specula checkout:

```bash
git fetch origin --tags
git checkout v1.2.0
uv tool install -e .
specula setup
specula --version
```

Rerun setup to refresh the skills and tools. Codex plugin users should select `plugin` again to refresh `specula-codex@specula`.

If you use the case-study archive or submodule-hosted tools, also run `git submodule update --init --recursive`.

## CI requirements and result interpretation

- Automatic Actions checks use a dedicated Linux self-hosted runner labeled `specula`, with Specula, an authenticated agent, and the target's build dependencies installed. Initialize under the runner account and keep the CI directory and saved agent sessions available. Each independently evolving branch needs its own CI directory.
- CI returns `2` for current `REPRODUCED` or `ENV_LIMITED` findings, including previously known unresolved bugs. `MASKED` findings produce a warning with exit code `0`. Incomplete checks return a nonzero exit code. Review `ci-report.md` and `ci-verdict.json` for evidence and checking limits; a completed bounded search does not establish exhaustive correctness.
- Persistent CI resumes with `--ci-dir` and `--run-id`; it does not support `--fresh-context`. Incremental runs use one agent profile and reject ordinary pipeline options that do not apply. Use `specula run --incremental --help` for supported options.
- Keep original BYOM inputs available and unchanged until initialization and any resume finish. BYOM requires isolated output and cannot be combined with skip options or `--incremental`.

## Installation limitations

Specula remains a source release installed from a persistent checkout with `uv tool install -e .`; plain wheel and PyPI installation are not supported. GitHub source archives omit submodule contents. Native Windows is not supported; use WSL2.
