# V0→V3 CI 演化实验阶段汇报

截至 2026-09-23，三个方向都有可执行产物，但原 goal 尚未完全验收。A 已在真实代码中复现；B 已有与其机制对应的公平循环模型反例，尚未做独立真实 API 复现。所有修改都在本实验目录，没有集成到 Specula 代码库。

## 1. Model 演化

已形成通用 JSON 测试协议、双向 runner，以及 Go/TLC 适配器。代码侧构造输入后测试模型；模型侧通过实际原模型动作生成输入/后继，再回放真实代码。先比较实际前状态与输入，再比较结果、后状态和消息。当前只实测 Go，单次输入/受控调度要求确定的可观察结果；多后继会明确报告 unsupported，不能任取一个结果当作一致。

V1、V2、V3 最终各运行 479 个代码侧实例和 174 个模型侧实例，均匹配，共 1,959 次比较。两条路线的输入有重叠，不能当作 1,959 个独立可达场景。这些是局部构造状态的一致性证据，不是完整系统等价证明。终止 panic 的内部缓冲顺序有单独说明。

发现并修复的模型问题包括 V2 竞选扫描被错误建模为正确实现、空 V2 的 transition 分类、零 cursor 的 auto-leave、删除再加入 learner 的 Progress 生命周期，以及把上一次 DropQuota 当成本次 append 的结果。修复后的 V1 仍通过全部 8 条历史 trace/4,629 事件，V2 通过 11 条/5,778 事件。Action 测试提供了这些历史 trace 没有覆盖的边界证据。

测试器也做了负对照：拒绝复用旧输出，失败进程不能贡献成功结果；TLC 多后继改为全部留存，修复了同一文件覆盖后可能误报匹配的问题。

主要产物：[框架说明](agent-runs/action-framework-final/README.md)、[最终矩阵](agent-runs/action-framework-final/out/final-results.json)。

## 2. Inv 演化

先对三个相邻更新做隔离的 Astra 初判，输入不含新版本 inv、gold 标签或其他调用结论。V0→V1、V1→V2 的预先列出的核心义务都被识别；V2→V3 的局部修改被识别，但自动退出的进展义务仍停留在 unresolved，没有形成可用性质。这不是一次明确说“不用改”的错误，不能夸大为已测得普遍漏改率。

随后让另一次调用不看旧 inv、根据更新独立生成相关性质。它补出了 C03：自动退出的义务要跨越领导者更换和延迟 ApplyConfChange，不能把 oldApplied<pending 当作进展前提。这个候选随后产生了对应 B 机制的模型反例。

修改验证采用真实状态/转移差分：执行实际 TLA 定义，记录旧 inv 与候选 inv 的不同真值，关联原代码/模型执行，并加入合法与非法相邻对照。12 组核心修改得到局部验证；132 个代码/模型回放对匹配，97 个旧/新性质真值检查及 102 个观察记录检查通过。“通过”包括正确拒绝非法观察，不表示实现满足全部性质。

具体例子：合法的 joint {1}/{1} 自选举被旧性质误报，修正后通过；修正仍拒绝 pending V2 下的竞选。故意弱化为只检查 legacy 配置则放过该错误。验证还拒绝了仅保留日志前缀就允许任意追加等过宽候选。

目前更合适的策略是：先判断并局部维护；对拟修改的性质进行状态差分与负对照验证；对未覆盖/未解决义务做定向独立生成。没有证据支持每次全量重写，也不能据三个更新推断直接判断普遍可靠。

主要产物：[局部验证报告](agent-runs/inv-evidence/out/report.md)、[初判评分](results/invariant-decisions/judgment-score.json)、[独立生成比较](results/invariant-decisions/blind-V03/comparison.md)。

## 3. 状态空间探索

原配置存在两种静态遗漏：普通 MC/选举专项未生成 V2 请求，更新专项虽生成 V2 却未启用竞选资格性质。普通安全性质也不能替代自动退出的进展义务。因此不能把所有漏检都归因于状态空间太大。

初步有效的方法是复用已有测试/trace 的输入前缀，从原模型 Init 重新执行，再在更新附近展开交互。A 使用经过完整 post-state 对应检查的 V1 trace 前缀，在任意前缀分叉到原 Campaign 动作。B 使用旧 trace 的输入重新执行 V3 模型，不把旧 post-state 当作 V3 事实；随后探索领导权转移、延迟应用和公平服务循环。

A 的搜索在约 40 秒、871 个不同状态后给出 209 步反例。GPT-5.5 通过真实 RawNode API 在 V1/V2/V3 各重复 3 次：pending V2 竞选发出更高 term 的票请求，使现有 leader 退位；legacy 对照阻止竞选。V0 没有 V2 API，只运行 legacy 对照。

B 对应的领导更换反例：旧 leader 的未提交 leave 被新 leader 的普通条目覆盖；新 leader 的 applied=pending=5，Advance 到 6 时检查 5<5 为假，之后公平地处理心跳、持久化、Ready 和应用，仍不再生成 leave。V3 搜索约 199 秒、3,236 个不同状态产生公平循环反例；相同场景的 V2 控制穷尽 3,177 个状态后通过。反例还使用原动作、不使用 VIEW 回放了前缀和额外循环，排除了单纯辅助 ID 合并制造反例的解释。真实代码后果尚待验证。

额外保留了延迟安装 AutoLeave 的进展反例，以及重复 leave 导致错误配置转换的模型线索；它们在旧版本也出现，不能全部归为 V3 新引入 bug。尚未完成这些线索及原 CR/MC 记录的统一代码回归。

普通 MC 的短预算基线没有找到目标，且已记录的进度仍很浅；但其参数和定向场景并不完全相同。目前没有完成严格同预算、同参数消融，不能宣称普遍优于普通 MC，更不能声称普通 MC 永远找不到。

主要产物：[A 代码复现](agent-runs/reproduce-A/out/confirmation.md)、[B/进展性质探索](agent-runs/progress-probe-V03/out/report.md)、[驱动与抽象审计](agent-runs/progress-probe-V03/out/driver-audit.md)。

## 成本与验收边界

已完成的独立调用为 9 次 GPT-6 Astra、1 次 GPT-5.5。累计约 178 万非缓存输入 token、3,969 万缓存输入 token、42 万输出 token；缓存输入是总输入的子集，推理 token 不重复计入输出。此统计不包含主协调会话，日志没有实际美元账单。

首次适配仍然较贵：V3 模型适配/修复调用约 36 分钟。固定后的 V3 六路旧/新对照重跑约 55 秒；最终同一版本的两个方向回归约 19–20 秒。Inv 最终代码/模型回放约 55 秒，成功真值检查约 145 秒。应分别评估首次建立成本和持续复用成本。

尚需完成：B 的 GPT-5.5 真实 API 复现及版本/普通日志进展对照；额外线索的代码回归与分类；统一最终模型、性质和搜索配置的回归；可比较的搜索消融。当前不应标记 goal complete。

上一轮主协调流程在 2026-09-22 20:33 UTC 被平台自动安全检查中断，记录为 possible cybersecurity risk，因此 goal 状态为 blocked。已经启动的独立实验随后正常结束，本报告纳入了这些返回结果。这不是已证明的技术不可行结论。
