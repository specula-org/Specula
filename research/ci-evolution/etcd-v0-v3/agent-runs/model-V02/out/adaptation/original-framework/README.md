This is a developmental local-action validation pilot. `runner.py` is independent of Raft, Go and TLA+. It runs command adapters, validates identities, compares mapped inputs/pre-states and complete declared observations, and saves full differences. It contains no protocol transition logic. `protocol.schema.json` describes the wire format. No extra Python packages or network access are required.

A case is a JSON object with `protocol: "action-validation/v1"`, stable `id`, `action`, `pre`, `input`, and provenance/reachability `meta`. Input files are JSON arrays. Each adapter writes one JSON result per line, with `id`, `engine`, `adapter_status`, `pre_observation`, `input_observation`, and `observation: {state, status, return}`. Successful model generation also includes `testcase`. Additional raw evidence fields are allowed. `adapter_status` distinguishes an executed case from adapter failure or unsupported setup; an expected implementation panic is an executed outcome, not an adapter error.

`manifest.json` supplies executable commands and explicit paths whose arrays are unordered. The runner sorts these arrays while retaining multiplicity; every other array is ordered. Missing/duplicate results, setup/input disagreements, and execution-output disagreements are distinct. Final human triage decides whether an output disagreement is a projection defect or a source/model behavioral mismatch. A runner verdict alone is not a bug claim.

To reproduce the final four runs from `/workspace` (use fresh output directories):

```sh
python3 out/framework/runner.py --manifest out/framework/targets/etcd/manifest.json --cases out/cases/code-inputs.json --output out/cases/replay-baseline-code --spec new/spec --route code-to-model
python3 out/framework/runner.py --manifest out/framework/targets/etcd/manifest.json --cases out/framework/targets/etcd/model-seeds.json --output out/cases/replay-baseline-model --spec new/spec --route model-to-code
python3 out/framework/runner.py --manifest out/framework/targets/etcd/manifest.json --cases out/cases/code-inputs.json --output out/cases/replay-repaired-code --spec out/repaired-spec --route code-to-model
python3 out/framework/runner.py --manifest out/framework/targets/etcd/manifest.json --cases out/framework/targets/etcd/model-seeds.json --output out/cases/replay-repaired-model --spec out/repaired-spec --route model-to-code
python3 -m unittest discover -s out/framework -p test_runner.py -v
```

For code-to-model, the runner executes Go first, then TLC evaluates the original model on corresponding inputs. For model-to-code, TLC selects from a finite symbolic domain and executes an actual original operator/action. It exports the selected case and computed successor; the runner then passes those cases to Go. `ModelDomains.tla` constructs inputs only. `LocalActions.tla` maps state and invokes `base` definitions; it never implements a replacement Raft transition. These are depth-two local state graphs (initial local state plus one action), not a full protocol model-checking campaign. `Emit` is an output hook registered as a TLC invariant, not a safety invariant or oracle. Original safety invariants are neither executed nor changed.

The Go adapter is maintained in `adapters/go/action_validation_test.go` and installed as a test file in `new/source`. It invokes unexported real functions using package-local Go tests. Build environment, outer timeout, and logs are recorded in every implementation work directory. It uses the historical dependency overlay with `GOPROXY=off`. TLC copies the supplied `base.tla` verbatim into a fresh work directory and records its Java command. Each invocation has one worker, a 2 GB heap and a 175-second outer timeout. Temporary/build files are directed into `/workspace/out`.

`out/cases/code-inputs.json` and `out/cases/model-inputs.json` are reusable regression inputs; retain their IDs across source/model versions. `domain.py` is optional regeneration of the code-derived domain. The model domain lives in `ModelDomains.tla` plus the target's `model-seeds.json`. Shared seed vocabulary intentionally makes the routes comparable; generation is not statistically independent. Never replace saved inputs merely because a version disagrees with them.

To adapt another language or system, keep `runner.py`, `protocol.schema.json`, and its tests. Regenerate the implementation adapter and model adapter; supply the new target's domain/observation descriptors and command manifest. Reuse cases only where their semantics and precondition mappings still apply; otherwise report `unsupported` explicitly. See `regenerate-adapters.md` for a constrained agent task. There were no other agents, external references, later source versions, or prior experiment histories used in this pilot.

Coordinator hardening: the runner and direct TLC adapter require new exclusive output/work directories. Failed commands never contribute partial exported results. Completed local relations with no successor export mapped input/pre-state and observation.status=disabled; these compare as behavioral mismatches against a corresponding executable implementation call. Invalid mappings and failed/unsupported adapters remain separate. Raw relation mismatch still requires human/source triage. Negative controls are in ../negative-controls/results.json and fresh four-route verification in ../coordinator-rerun.json.
