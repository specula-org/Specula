The supported domain uses server IDs 1–4, local ID 1, election/heartbeat ticks 10/1, inflight capacity 2, message/Ready cap 1024, uncommitted cap 16, and safe reads. CheckQuorum and PreVote are explicit pre-state fields. Votes include real/pre-votes, stale/future/current terms, repeated/conflicting votes, log freshness, lease suppression/expiry, forced transfer context, and recipients that are learners, voters, staged learners or removed members. The candidate's actual tracker counts responses under its own incoming/outgoing configuration; current learners do not count.

`pre` is a locally injected boundary state built using real MemoryStorage/NewRawNode plus package-local assignments. `audit_inputs.py` checks configuration shape, both halves, learners, staged learners, progress membership, log indices/terms, quota backing and bounds. This is necessary, not sufficient, for distributed reachability. Synthetic log/configuration combinations, leader states and Ready read results are not a proof of reachability. The six `invalid-inputs.json` cases intentionally violate ConfState constraints and are reported separately. Empty incoming configurations, overlapping voters/learners and staged learners without joint state are unsupported normal inputs. All 342 supported direction instances pass structural audit.

Node schedules use a Status request/response after Ready, each intervening operation and Advance. This guarantees the prior select branch finished; no tick producer or concurrent external caller runs. Intervening heartbeat, proposal, read acknowledgement, higher-term heartbeat and combined schedules run through the actual Node channels. Internal `node.step` allows explicit local MsgBeat; this is a scheduler boundary test, not a claim that public Node.Step accepts local messages. There is no schedule enumeration. Cancellation, removed-node proposal gating and arbitrary concurrent callers remain uncovered. Node's asynchronous intermediate proposal delivery does not return the core proposal error; RawNode's drop is retained as raw evidence and subsequent operations proceed.

The common state projection covers configuration, learner flag, term/vote/role/leader, committed/applied/pending cursors, quota, transfer, visible/stable/unstable log, snapshot, full progress including inflights, outgoing messages, pending reads and acknowledgements, read states, prevHS/prevSS, elapsed counters, configuration flags and recorded votes. MemoryStorage entries, snapshot, HardState and cut are included. Go measures entry sizes using the actual protobuf encoder. Legacy entries have six payload bytes; V2 has two plus six per change in this domain. Empty stored normal payloads are nonnil (encoded size eight); internally generated nil payloads have size six, selected through the retained adapter constant override. Auto-leave has two payload bytes and ten encoded bytes.

Ready returns include changed HS/SS, unstable and committed entries, snapshot, messages, read states, MustSync and applied cursor. Advance's input observation additionally contains the actual captured Ready batch. Its return observation is a synthetic ownership observation `batchAfter`, obtained by reading that same Go Ready after Advance; it is not a public API return. This verifies that intervening live output and the retained batch stay distinct, including duplicate messages/read results. The model compares the actual original Ready result, not a manufactured batch. Persistence flags and storage writes are caller-environment mappings. Setup installs the supplied log into MemoryStorage; the unstable overlapping suffix represents persisted but not yet acknowledged entries. Before Advance, the caller installs any captured HardState. This does not model disk failure or write ordering.

Restart has a different pre-observation: actual MemoryStorage contents and the actual constructor option values passed to NewRawNode. It does not pretend the unused live setup object is constructor input. The model compares snapshot-backed disk contents and corresponding fixed options. Input HardState term is three, vote zero, commit the snapshot index. Snapshot histories in the model are synthetic ghosts; only metadata, surviving entries and bounds are compared. No disk I/O or application replay is exercised. A panicking constructor returns no new object; invalid-domain state projections are diagnostic only.

Messages are multisets; duplicate counts are preserved. Configurations, progress, votes and read acknowledgement sets are unordered; logs, changes, pending-read order, read-result order and inflights are ordered. Captured batch message/config collections have the same canonicalization. CampaignTransfer is mapped to an explicit `forced` boolean with context ID zero; ordinary contexts are integer read IDs. Arbitrary data/context bytes, unknown protobuf fields, remote read-index responses and snapshot data are outside this mapping. Response inputs in the supported domain come from tracked members; RawNode's local-message and unknown-peer errors are not independently covered.

Status is separate from state/return: ok, proposal dropped, panic, error or model disabled. Panic text is raw evidence; model configuration errors abstract several exact Go errors. A void Advance remains ok even when its internal automatic-leave append encounters quota. Model candidates are exported before and after prerequisite preparation, so disabled Ready preparation cannot silently remove a generated case. A completed relation without a successor is an explicit disabled result; a nonzero TLC process exit is an adapter failure. The empty public RawNode Ready/Advance pair is supported by the behavior repair; an empty Node Ready delivery remains disabled because node.run requires HasReady.

Random election timeout is fixed for initial setup; Go resets may choose 10–19. Timeout/RNG state is excluded because no subsequent ticking action tests that choice. Tick counters are compared. Slice allocation/capacity, function pointers, log output and tracker map order are excluded. Borrowed Ready slice contents are observed, but arbitrary backing-array mutation/reentrant API abuse is not modeled. Domains share vocabulary across routes, so the routes are not statistically independent and correlated mapping mistakes remain possible.

Old/new comparisons explicitly bind both provided sources. They are a 21-case semantic delta subset, not a repeat of the coordinator's V01 certification. Unchanged `numOfPendingConf` still ignores V2 entries. Fresh live snapshots still reject outgoing-only and staged outgoing-only recipients; restart now reconstructs them. These source-backed behaviors are retained. No injected state alone is labeled a real distributed system bug.

Remaining coverage: no global search, safety checking, distributed reachability traces, elections/network/crash schedules, arbitrary pagination boundaries, post-restart application replay, ReadIndex cancellation/lease reads, disk failures or broad transport inputs. The action domain is limited to four servers; supplied package tests cover additional quorum/restore cases, but are not extra bidirectional instances. Observer ghosts and invariant predicates remain outside the comparison; a proposed auto-leave observer correction is recorded separately and unapplied.
