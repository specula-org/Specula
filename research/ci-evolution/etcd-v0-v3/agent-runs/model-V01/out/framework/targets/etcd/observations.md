All cases use server IDs 1–4, local ID 1, election/heartbeat ticks 10/1, inflight capacity 2, message/Ready caps 1024 bytes, uncommitted cap 16 bytes, safe reads, no forwarding suppression and no CheckQuorum/PreVote configuration flags except the explicit pre-vote case field. The CheckQuorum action is invoked explicitly. Entry indexes/terms fit one-byte varints. Legacy changes have six payload bytes; V2 has two bytes plus six per single change. Go actually marshals and measures each input and its log/Ready/message entries; the runner separately checks input mapping. Normal-entry data is zero-filled of the chosen length. Empty stored normal payloads are nonnil (eight-byte entries); internally generated nil normal payloads are six-byte entries. The adapter overrides only the model's concrete `EmptyEncoded` size, not behavior. Auto-leave uses two payload bytes and ten encoded bytes.

`pre` describes an injected, serialized local boundary state. Setup uses real `MemoryStorage`/`NewRawNode`, then package-local test assignments for volatile state that public constructors cannot represent, including joint progress and pending indexes. `audit_inputs.py` checks configuration/progress shape, contiguous nondecreasing log terms, applied/committed/last bounds, payload backing for quota, and inflight bounds. It does not determine distributed reachability or serve as a transition oracle. Some combinations can require unusual histories, and none carries a proof of reachability from `ProtocolInit`. Configuration history, durable-quorum evidence and other model ghosts are not fabricated as correctness evidence. The initially generated over-quota and decreasing-term descriptors were corrected before the final runs; earlier attempts remain diagnostic evidence only.

The common projection compares term, vote, role, leader, configuration, self learner flag, commit/applied/pending indexes, quota, transfer target, observable log entries, first/last indexes, unstable entries/offset/snapshot, each peer's Match/Next/mode/probe/pending/active/learner/inflight values, outgoing messages, read queue and acknowledgements, read states, prevHS/prevSS, election/heartbeat counters, pre-vote flag, recorded votes, and MemoryStorage entries/snapshot/HS/cut. Returned values and ok/drop/panic status are separate. Exact panic text is raw evidence: the model abstracts several concrete Changer errors as `invalid configuration transition`. It must still agree on panic occurrence and unchanged/changed state. An internal failed auto-leave append is observable via state and model `raw_fatal`/Go logs; Advance itself is void and is not an API drop.

The caller owns persistence. Before an Advance test, Go obtains an actual Ready, optionally accepts it as Node does, and installs its HardState into MemoryStorage. Its entries are already installed by setup, representing completed caller persistence. TLC captures `NewReady` and installs matching caller flags/storage for `ProtocolAdvance`; it does not handcraft an unrelated cursor. The independently compared pre-state is at the entry to the tested action. Node tests call the exact `acceptReady`/`commitReady` helpers used in `node.run`, but do not exercise goroutine/select/channel scheduling or proposal-channel gating. `RawNode.Ready` tests contain no intervening mutation before Advance. Reentrant/invalid caller use is not endorsed or tested.

For restart, the model's `disk[1]` and Go's constructor storage are both built from `input.snapshot`, with HardState term 3 and commit at the snapshot index. The output compares the reconstructed MemoryStorage too. Model full snapshot histories are synthetic ghost prefixes with the snapshot's term; only snapshot metadata, log bounds and the concrete surviving entries are observable. Snapshot data is empty. Restore's boolean mapping is valid only for this domain's initially empty unstable snapshot; a domain with existing unstable snapshots needs an explicit restoration-outcome mapping.

Messages are compared as multisets, preserving duplicate counts. All wire fields used here are mapped: type, from/to, term, index/logTerm, commit, reject/hint, context, entries and snapshot metadata. Configuration and vote/progress collections are unordered; logs, change batches, read queues and inflights remain ordered. Go map iteration and TLC CHOOSE order are thus excluded only where order has no semantic role. Randomized election timeout is fixed to 10 during setup; resets may choose any 10–19 in Go. The timeout value and random-generator state are excluded because these single actions do not subsequently tick. Clocks themselves are compared.

Excluded/unsupported dimensions and expansion tasks:

- Model ghosts (`history`, `quality`, witness prefixes, `cfgHist`, durability obligations), application queues, channel state and sequence IDs have no direct Go-core observation. Ready and Advance caller effects are mapped explicitly; add end-to-end caller schedules before claiming wrapper conformance.
- Progress inflight allocation layout, slice capacity/aliasing, logger state, function pointers and goroutine scheduling are hidden implementation details. Logical inflight contents are read via reflection and compared; allocation and mutation ownership beyond the tested boundary are not checked.
- Context and normal data bytes are represented by integer read IDs or payload length. Legacy context/ID, V2 context/unknown protobuf fields, and arbitrary application data are unsupported. Add byte-preserving mappings before testing serialization compatibility or remote read responses. Current reads are local.
- Restore/restart covers joint metadata loss, omitted outgoing-only recipient, learner membership, obsolete snapshot, matching-term fast-forward and non-follower defense. It does not cover actual disk I/O failures, snapshot data, compaction availability, snapshot creation, post-restart application replay or a complete joint-recovery history.
- Bootstrap construction, Node handoff/cancellation, status APIs, append-response commit paths, elections by received vote responses, lease reads, transfer schedules, and crash/network concurrency are not tested as independent families. Commit/broadcast on configuration application and joint quorum decisions are covered locally.
- The old snapshot/spec were inspected for the diff, not replayed. Saved JSON inputs can be reused across versions, but this Go adapter binds to the new snapshot's API. An old-version adapter must explicitly translate supported legacy cases and report V2 cases unsupported.

No exclusions are silent mismatch suppression. The runner compares the complete declared projection and stores every difference; adding a field to the projection can expose a new adapter error or real model discrepancy.
